# Crash Game Bot (عملة وهمية فقط)

بوت تيليجرام للعبة "الصاروخ/Crash" بعملة افتراضية (Coin) — بدون فلوس حقيقية،
بدون TON حقيقي، بدون أي دفع أو سحب فعلي. رصيد كل يوزر مجرد رقم بقاعدة بيانات محلية.

## المكونات

| ملف | الوظيفة |
|---|---|
| `bot.py` | البوت نفسه (Aiogram 3.x): `/bet`, `/balance`, `/history`, أوامر الأدمن |
| `game_logic.py` | معادلة صعود المضاعف + توليد نقطة الانفجار (crash point) بطريقة provably-fair |
| `db.py` | طبقة SQLite (users / transactions / rounds) — نسخة async للبوت + نسخة sync للوحة الويب |
| `admin_panel.py` | لوحة تحكم ويب (Flask) لإدارة الأرصدة بالـ user_id |
| `templates/*.html` | صفحات لوحة التحكم |
| `webapp/index.html` | واجهة Mini App متحركة (صاروخ + نجوم) — عرض فقط، القرار الحقيقي بالسيرفر |
| `webapp_api.py` | Flask API تفتح منه اللعبة كـ Web App داخل تيليجرام: `/api/bet`, `/api/round/<id>`, `/api/round/<id>/cashout`, `/api/balance` — يتحقق من توقيع `initData` قبل ما يثق بأي user_id |

## تشغيل زر "افتح اللعبة" (Web App)

1. تليجرام **يرفض** فتح أي WebApp على رابط http:// عادي — لازم رابط HTTPS عام.
   لو تختبر محليًا استخدم `ngrok http 8090` واخذ الرابط المؤقت.
2. حط الرابط بـ `.env` تحت `WEBAPP_URL=https://...` (نفس الرابط اللي يوصل لـ `webapp_api.py`).
3. شغّل الثلاث خدمات كل وحدة بعملية منفصلة:
   ```bash
   python bot.py            # البوت
   python webapp_api.py      # سيرفر اللعبة (Web App) - أو gunicorn -w 2 -b 0.0.0.0:8090 webapp_api:app
   python admin_panel.py     # لوحة التحكم
   ```
4. اكتب `/start` أو `/play` بالبوت → بيطلعلك زر "🚀 افتح اللعبة" يفتح صفحة الويب داخل تيليجرام
   مباشرة (بدون ما يطلع من التطبيق)، فيها نفس الرصيد الحقيقي والرهان الحقيقي —
   كل القرار (الانفجار، المضاعف) يتحسب بالسيرفر بـ `webapp_api.py`، والصفحة تسأل
   كل 300ms عن الحالة، ما تحسب شي بنفسها.

## التشغيل محليًا / على Termux

```bash
pip install -r requirements.txt
cp .env.example .env
# عدّل .env: حط BOT_TOKEN و ADMIN_IDS (الـ user_id مالك انت بتليجرام)

python bot.py            # شغّل البوت
python admin_panel.py     # بمحطة ثانية: شغّل لوحة التحكم (منفذ 8080)
```

## التصميم 3D

`webapp/index.html` الحين يستخدم **Three.js** (رسم 3D حقيقي بالمتصفح عن طريق WebGL)
مو Canvas 2D بسيط:
- صاروخ مبني من أشكال هندسية 3D (مخروط + أسطوانة + زعانف) بإضاءة وتوهج بنفسجي/أزرق.
- كاميرا تتبع الصاروخ وهو يصعد بمنظور عمق حقيقي (parallax + fog).
- نجوم خلفية 3D تدور ببطء.
- انفجار جسيمات (particle burst) عند الخسارة، وانفجار أخضر عند نجاح السحب.

هذا تصميم أصلي من الصفر — **ما نسخت ولا اطلعت على تصميم أي بوت ثاني** (ما عندي وصول
لمحتوى بوتات تيليجرام الخاصة أصلاً). لو تبي تعديل شكل الصاروخ أو الألوان، كلها بأول
150 سطر من قسم `<script>` بالملف، بمتغيرات `bodyMat` / `accentMat` / `finMat`.

## اسم وصورة اللاعب + زر دائم بأسم البوت

- **الاسم والصورة**: تيليجرام يبعتهم تلقائيًا وقت فتح الـ Mini App (`initDataUnsafe.user`) -
  ما نحتاج نطلب صلاحية أو نسوي طلب إضافي. يطلعون فوق يمين الشاشة بالـ webapp.
  إذا الشخص ما عنده صورة بروفايل، يطلع حرف أول اسمه بدائرة بدالها.
- **الزر الدائم**: عند تشغيل `bot.py`، البوت يسوي `set_chat_menu_button` تلقائيًا -
  يعني يطلع زر "🚀 العب الآن" جنب صندوق الكتابة لكل مستخدم، دايم موجود
  (مو بس لما يسوي `/start`). هذا نفس تأثير إعداد "Menu Button" من BotFather،
  بس مسوّينه بالكود عشان يتظبط تلقائي بكل مرة تشغّل فيها البوت.

### بديل: رابط مباشر يفتح اللعبة بدون فتح الشات

لو تبي رابط تكدر ترسله لأي حد (`t.me/YourBot/game`) يفتح اللعبة مباشرة:
1. روح لـ **@BotFather** → `/newapp`
2. اختر بوتك → حط اسم قصير للتطبيق (مثلاً `game`)
3. حط نفس رابط `WEBAPP_URL` مالك لما يطلبه
4. تصير عندك رابط دائم: `https://t.me/اسم_البوت/game`

## النشر على Render (اللي تستخدمه حاليًا)

عندك `webapp_api.py` منشور على `https://crash-bot-a2wt.onrender.com` - هذا فقط
سيرفر اللعبة (API). البوت (`bot.py`) لازم يشتغل بمكان ثاني منفصل، لأنه polling
مستمر مو موقع ويب عادي. الخطوات:

1. **بلوحة Render** لخدمة `crash-bot-a2wt` → تبويب **Environment** → ضيف:
   ```
   BOT_TOKEN=توكن_البوت_من_BotFather
   ADMIN_IDS=الـ_user_id_مالك
   STARTING_BALANCE=1000
   MIN_BET=10
   MAX_BET=100000
   CURRENCY_NAME=Coin
   ```
   (لا تحط `WEBAPP_URL` هنا - مو مطلوب لهذي الخدمة، هي بس تستقبل الطلبات)

2. تأكد **Start Command** بـ Render مضبوط على:
   ```
   gunicorn -w 2 -b 0.0.0.0:$PORT webapp_api:app
   ```
   (موجود جاهز بملف `Procfile` المرفق - Render يقراه تلقائيًا لو نوع الخدمة "Web Service").

3. **بمكان تشغيل البوت** (جهازك، Termux، أو VPS - مو Render نفسه إذا الخطة مجانية،
   لأن خدمات الويب المجانية بـ Render تنام بعد 15 دقيقة خمول ومو مناسبة لبوت
   دايم الاتصال؛ لهذا تحتاج "Background Worker" بخطة مدفوعة، أو تشغّله مكان ثاني):
   ```
   WEBAPP_URL=https://crash-bot-a2wt.onrender.com
   BOT_TOKEN=نفس_التوكن
   ADMIN_IDS=نفس_الايدي
   ```
   وشغّل: `python bot.py`

4. جرّب `/start` بالبوت → اضغط "🚀 افتح اللعبة".

⚠️ **مهم:** أول فتح بعد فترة خمول (Render Free) بياخذ ٢٠-٣٠ ثانية "تصحية" السيرفر
(cold start) - إذا الصفحة طلعت بيضا أول ثانية، هذا طبيعي وليس خطأ بالكود. لو تبي
تلافيها كليًا لازم خطة Render مدفوعة ما تنام، أو تسوي ping دوري للسيرفر كل ١٠ دقايق.

## النشر على AlwaseData (أو أي شير هوستنغ Python)

1. ارفع مجلد المشروع، وسوّي virtualenv وثبّت `requirements.txt`.
2. البوت يشتغل بـ polling (`dp.start_polling`) — يحتاج عملية دائمة (long-running process)،
   مو WSGI عادي. أغلب شير هوستنغ ما يدعم هذا مباشرة؛ تحتاج خدمة "Worker/Task" دائمة
   (بعض خطط AlwaysData توفر "Custom" process type لهذا الغرض) أو VPS بسيط مع `systemd`/`screen`/`tmux`.
3. لوحة التحكم (`admin_panel.py`) نفسها WSGI عادي — تكدر تربطها بـ gunicorn خلف Nginx:
   ```bash
   gunicorn -w 2 -b 0.0.0.0:8080 admin_panel:app
   ```
4. **حط الموقع خلف HTTPS دائمًا** قبل ما تفتحه على النت — فيه فورمات لإضافة/تصفير أرصدة.

## أوامر الأدمن بالبوت (تطابق طلبك بالضبط)

- `/addbalance USER_ID AMOUNT` → يضيف مبلغ لرصيد أي شخص عن طريق الـ ID.
- `/setbalance USER_ID AMOUNT` → يثبّت الرصيد على رقم معين.
- `/resetbalance USER_ID` → يصفّر الرصيد بالكامل.
- `/userinfo USER_ID` → يعرض رصيد وإحصائيات أي لاعب.

كل هذي الأوامر محصورة على الـ `ADMIN_IDS` المكتوبة بـ `.env` — أي حد ثاني يرسلها ما يصير شي.

نفس العمليات موجودة بلوحة التحكم على الويب (`/user/<id>`) بفورمات "إضافة / تثبيت / تصفير".

## ليش "3D" بالضبط؟

اللي بنيته هو Canvas 2D متحرك (نجوم + صاروخ متوهج + جسيمات) داخل Telegram Mini App —
هذا أخف وأسرع تحميل وأنسب لهاتف عادي. "3D" حقيقي (WebGL/Three.js) ممكن نضيفه بعدين
كطبقة منفصلة إذا تبيه فعلاً، بس يزيد حجم التحميل واستهلاك البطارية على الموبايل بدون
فايدة حقيقية للعبة نوعها 2D بطبيعتها.

## نقاط ضعف معروفة (Failure modes) — اقرأها قبل ما تنشرها لناس حقيقيين

- **SQLite + WAL**: يكفي لعدد مستخدمين متوسط. لو الأعداد صارت كبيرة (آلاف يلعبون
  بنفس اللحظة)، تحتاج تنتقل لـ PostgreSQL — القفل `asyncio.Lock()` الحالي يسلسل كل
  عمليات الرصيد وممكن يصير عنق زجاجة.
- **Telegram edit-message rate limit**: التحديث كل 0.4 ثانية آمن لعدد جولات متزامنة
  محدود؛ لو صار عندك مئات الجولات النشطة بنفس الوقت لازم تجمّع التحديثات (batching)
  أو تنتقل لـ WebSocket داخل الـ Mini App بدل تعديل رسائل تيليجرام.
- **لا يوجد Idempotency على cashout**: لو الشبكة تهنّجت والزر انضغط مرتين بسرعة،
  الكود الحالي يحمي بـ `state.cashed_out` (in-memory) — بس لو البوت انريستارت
  بمنتصف جولة نشطة، تلك الجولة تضيع (raund state موجودة بالذاكرة مو بقاعدة البيانات).
  لأي بيئة إنتاج حقيقية: احفظ حالة الجولة (round state) بقاعدة البيانات مو بمتغير Python.
- **لوحة التحكم بدون HTTPS/2FA**: حاليًا يوزر/باسورد بسيط بجلسة Flask. كافي للتجربة
  الشخصية، مو كافي إذا فتحتها على دومين عام بدون طبقة حماية إضافية (VPN أو IP allowlist).
